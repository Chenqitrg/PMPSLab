# Reference ownership tree implementation plan

> Implement inline with executing-plans and test-driven-development. No commits.

**Goal:** A tree of RecordRef nodes, with separate input links and metadata-only display.
**Spec:** User-approved discussion: AlgorithmRef → ExecutionRef → StateRef →
SnapshotRef / MeasurementRef; one direct parent per node, optional cross-branch
initial_state. No automatic config deduplication. Explicit store everywhere;
no ExecutionRecord, no Ref carrying a store object, no compatibility requirements.
**Architecture:** Existing index tables store nodes. Each has one typed parent
link (kind, id); children are derived, not persisted. Refs remain (store_id, id).
Configuration/result binaries and frontend JSON remain unchanged in role.
**Tech:** Existing Julia 1.12, JSON, Serialization and AlgorithmConfigLab only.

## Constraints

- Each AlgorithmRef denotes one fixed copied config; explicit reuse for multiple runs.
- New runs may reference initial_state in another branch, without moving/duplicating it.
- record_state! requires an execution. Each measurement/snapshot requires a state.
- Tensor capture copies before async handoff; writing tensor bytes stays explicit.
- Store metadata can establish provenance, not prove actual external algorithm behavior.
- Data operations stay synchronous; scheduling, checkpoint restore and numerical code
  remain outside this package. One coordinated writer handle.
- No package version bump, commit, new dependencies, legacy aliases, migration layer.
- No broad numerical tests. English REPL examples; bounded metadata-only display.

## Interfaces

- AlgorithmRef = RecordRef{:algorithm}, StateRef = RecordRef{:state}; replace InputRef.
- record_algorithm!(store, config; label, constructors, metadata) → AlgorithmRef.
  Store detached immutable-top-level config as JSON+Julia; load_algorithm restores it.
- record_execution!(store, algorithm; initial_state=nothing, label, provenance) →
  ExecutionRef. No runtime wrapper or config duplication. finish_execution! unchanged.
- record_state!(store, execution; step, label, metadata) → StateRef.
- capture(state, tensor) remains a pure detached copy. StateSnapshot carries state ref,
  UUID and payload only. save_snapshot!(store, captured) publishes a child of state.
- measure!(store, definition, captured/saved) derives its state parent. Raw synchronous
  measure!(store, definition, input; state) requires an existing StateRef.
  start_measurement!(store, definition, state; input_snapshot, constructors, metadata)
  records one parent and an optional input link, never repeated execution/step fields.
- pin_snapshot! records a pin child of snapshot. Retention checks derive its state.
- parent_ref(store, ref), children(store, ref) are qualified inspection methods.
- showtree(io, store, root=nothing; maxdepth=8, maxnodes=100) renders metadata only.
  display(store) uses it automatically; compact show and Ref displays stay unchanged.
  Cross-links are arrow leaves, never recursively expanded. No new tree wrapper type.

## Review focus

1. Invalid/cross-store/missing parents and input links fail before publishing bytes.
2. Equal configs stay distinct; explicit shared config permits multiple executions.
3. Parent-only ancestry remains traversable after tensor pruning; payload unavailable
   is different from provenance missing. Pins still share existing bytes.
4. Display never deserializes payloads; bounds apply even for wide/deep histories;
   subtree display does not expand cross-branch input links.
5. Existing capture ownership, binary restoration and failure publication semantics
   survive the change. Prior completed consumers' records cannot be overwritten.
